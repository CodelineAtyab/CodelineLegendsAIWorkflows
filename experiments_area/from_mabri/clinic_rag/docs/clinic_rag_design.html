Clinic RAG Blueprint

A customer asks the clinic a question. We find the most similar text chunks from the clinic's PDFs in Qdrant, and gpt-4.1-mini answers using only those chunks. Ingestion runs once to fill Qdrant; the LangGraph workflow runs once per question.

Step-by-step workflow

You type the code in ingest.py and clinic_rag.py (the issue's rule). Claude sets things up, gives hints for one step at a time, and reviews each one.

  1. done

    0 · Setup

    Branch feature/306-mabri-clinic-rag-langgraph, uv project, dependencies, .env.example, 3 sample PDFs, Qdrant running in Docker.

  2. done

    1.1–1.3 · Constants, load_pdf_text, split_into_chunks

    Read each PDF's text and cut it into overlapping 500-character chunks. A 1,200-character text gives 3 chunks, and a break stops the loop once a chunk reaches the end, so no duplicate tail chunk is made.

  3. next · needs key

    1.4–1.6 · embed_texts, store_chunks, main

    Turn each chunk into a 1536-number vector, upsert into clinic_docs, print opening_hours.pdf: N chunks stored.

  4. later

    2.1–2.8 · State, nodes, wiring, diagram

    TypedDict state, the retrieve / generate / no_answer nodes, the decider, StateGraph wiring, compile, and clinic_rag.png. You can draw the graph before the key arrives.

  5. later

    2.9 · Five questions

    Friday hours, walk-ins, cancelling, a price, and car insurance (which should take the no_answer path). Tune RELEVANCE_THRESHOLD using the real scores.

  6. later

    3 · README, review, PR

    Write the README with your real answers, check that no key is staged, commit, and open a PR with Closes #306.

How to run

Everything runs in PowerShell from experiments_area\from_mabri\clinic_rag. You need Docker Desktop running and an OpenAI key from Atyab. The key goes only in .env, which git ignores.

One-time setup

Terminal 1 · project folder
cd experiments_area\from_mabri\clinic_rag
uv sync
Copy-Item .env.example .env

Then open .env and replace your-key-here with the real key. Never paste it anywhere else.

1 · Start Qdrant

Terminal 1
docker run -d --name clinic-qdrant -p 6333:6333 -v qdrant_storage:/qdrant/storage qdrant/qdrant
Already created? Use docker start clinic-qdrant. Check it at localhost:6333/dashboard.

2 · Ingest the PDFs (once, or after changing a PDF)

Terminal 1
uv run ingest.py
Expected output (counts depend on your chunk size):
booking_policy.pdf: 3 chunks stored
opening_hours.pdf: 2 chunks stored
services_and_prices.pdf: 2 chunks stored

3 · Ask the questions

Terminal 1
uv run clinic_rag.py
Expected: clinic_rag.png is saved, then one dict for each question.
{'question': 'What time do you open on Friday?',
 'chunks': ['... Friday: the clinic is open from 2:00 PM to 9:00 PM ...'],
 'answer': 'On Friday we open at 2:00 PM and close at 9:00 PM.'}
{'question': 'Do you sell car insurance?', 'chunks': [],
 'answer': 'Sorry, I could not find that in our documents. Please contact the clinic ...'}

Stop and clean up

Terminal 1
docker stop clinic-qdrant
docker rm clinic-qdrant
docker volume rm qdrant_storage

Run only the first line to pause. The last line deletes the stored vectors, so you would need to run ingestion again.
